# C# Test Task Solution

Решение тестового задания: три независимые задачи и консольный запуск для проверки обработки лог-файлов.

## Структура проекта

```text
CSharpTestTaskSolution/
├── task_1/
│   └── task_1_RleCodec.cs          # Задача 1: компрессия и декомпрессия строки
├── task_2/
│   └── task_2_Server.cs            # Задача 2: потокобезопасный сервер-счётчик
├── task_3/
│   └── task_3_LogStandardizer.cs   # Задача 3: стандартизация лог-файлов
├── tests/
│   └── ManualTests.cs              # Ручные тесты без внешних зависимостей
├── Program.cs                      # Точка входа консольного приложения
├── CSharpTestTaskSolution.csproj   # Файл проекта .NET
└── README.md
```

## Требования

- .NET SDK 8.0 или новее.
- ОС: Windows, Linux или macOS.

## Быстрый старт

Перейдите в папку проекта:

```bash
cd CSharpTestTaskSolution
```

Соберите проект:

```bash
dotnet build
```

Запустите ручные тесты:

```bash
dotnet run -- --test
```

Ожидаемый результат:

```text
All manual tests passed.
```

## Запуск стандартизации логов

```bash
dotnet run -- <input.log> <output.log> [problems.txt]
```

Пример:

```bash
dotnet run -- input.log output.log problems.txt
```

Где:

- `input.log` — входной файл с логами в одном из двух поддерживаемых форматов.
- `output.log` — файл, куда записываются валидные строки в стандартизированном формате.
- `problems.txt` — необязательный путь к файлу для невалидных строк. Если путь не указан, файл создаётся рядом с выходным файлом.

## Задача 1 — RLE-компрессия

Файл: `task_1/task_1_RleCodec.cs`.

Реализованы методы:

- `Compress(string source)` — сжимает строку из маленьких латинских букв.
- `Decompress(string compressed)` — восстанавливает исходную строку из канонической сжатой формы.

Особенности:

- проверяется `null`;
- проверяются допустимые символы `a-z`;
- поддерживаются многозначные длины групп;
- некорректная сжатая строка отклоняется исключением.

Сложность:

- время: `O(n)`;
- память: `O(n)` для результата.

## Задача 2 — потокобезопасный сервер-счётчик

Файл: `task_2/task_2_Server.cs`.

Реализованы методы:

- `GetCount()` — параллельное чтение;
- `AddToCount(int value)` — эксклюзивная запись;
- `ResetForTests(int value = 0)` — вспомогательный метод для тестирования.

Используется `ReaderWriterLockSlim`: несколько читателей могут читать одновременно, но запись выполняется только одним потоком и блокирует читателей до завершения.

Сложность:

- время операции чтения/записи: `O(1)` без учёта ожидания блокировки;
- память: `O(1)`.

## Задача 3 — стандартизация лог-файлов

Файл: `task_3/task_3_LogStandardizer.cs`.

Реализованы методы:

- `StandardizeFile(string inputPath, string outputPath, string? problemsPath = null)` — потоковая обработка файла;
- `TryParse(string line, out StandardLogRecord record)` — разбор одной строки.

Поддерживаются два входных формата:

1. `dd.MM.yyyy HH:mm:ss.ffff LEVEL message`
2. `yyyy-MM-dd HH:mm:ss.ffff| LEVEL|threadId|method| message`

Выходной формат:

```text
Дата<TAB>Время<TAB>Уровень<TAB>ВызвавшийМетод<TAB>Сообщение
```

В проекте дата выводится в формате `dd-MM-yyyy`, потому что в условии указано `DD-MM-YYYY`. Если проверяющая система ожидает формат из примера `yyyy-MM-dd`, достаточно изменить константу `OutputDateFormat` в `task_3/task_3_LogStandardizer.cs`.

Сложность:

- время: `O(N * L)`, где `N` — количество строк, `L` — средняя длина строки;
- память: `O(L)`, так как файл читается построчно.

## Тестирование

В проекте есть набор ручных тестов:

- проверка компрессии/декомпрессии;
- проверка ошибок в невалидных строках;
- конкурентное чтение и запись счётчика;
- разбор валидных и невалидных логов.

Запуск:

```bash
dotnet run -- --test
```

- Валидация и исключения добавлены намеренно, так как в задании отдельно оцениваются оформление, тестирование и устойчивость решения.
